## Question 1

What are the two main parts of architecture documentation, as described in the text?

- [ ] User manuals and technical specifications.
- [x] The central architecture description and the architecture overview.
- [ ] Design patterns and architectural styles.
- [ ] Functional requirements and non-functional requirements.

<details>
<summary>Rationale</summary>
<p>

**Rationale:** Architecture documentation consists of central architecture description (detailed,
comprehensive) and architecture overview (concise, 30 pages max). User manuals, design patterns, and
requirements are separate documentation types.

</p>
</details>

## Question 2

What is the primary characteristic of the "central architecture description"?

- [ ] It is limited to a maximum of 30 pages.
- [x] It is very detailed and encompasses all relevant information about the architecture, including
  objectives, quality requirements, design decisions, and utilized patterns.
- [ ] It is primarily used for communicating with non-technical stakeholders.
- [ ] It is only created for a specific purpose and not maintained over time.

<details>
<summary>Rationale</summary>
<p>

**Rationale:** Central architecture description is detailed and comprehensive (objectives, quality
requirements, decisions, patterns). Page limits (overview), non-technical communication, and
temporal limitations all contradict its comprehensive reference purpose.

</p>
</details>

## Question 3

What is the primary characteristic of the "architecture overview"?

- [ ] It is very detailed and comprehensive.
- [x] It is concise and limited to a maximum of 30 pages, outlining fundamental structures and key
  decisions.
- [ ] It is only for internal use by the development team.
- [ ] It replaces the need for the central architecture description.

<details>
<summary>Rationale</summary>
<p>

**Rationale:** Architecture overview is concise (30 pages max), outlining fundamentals and key
decisions. Detailed comprehensiveness, internal-only use, and central description replacement all
contradict its concise stakeholder-oriented purpose.

</p>
</details>

## Question 4

What is the purpose of the "architecture wallpaper"?

- [ ] To serve as a decorative element in the office.
- [x] A large diagram combining building block and deployment views, showcasing multiple
  architecture aspects in one visual.
- [ ] A detailed textual description of the system's architecture.
- [ ] A document for tracking project progress.

<details>
<summary>Rationale</summary>
<p>

**Rationale:** Architecture wallpaper combines Building Block and Deployment views in one large
diagram showcasing multiple aspects. Office decoration, textual descriptions, and progress tracking
all miss its multi-view visual integration purpose.

</p>
</details>

## Question 5

What is the primary purpose of the "manual for architecture documentation"?

- [ ] To provide a high-level overview for stakeholders.
- [x] To serve as a practical handbook for those who maintain the documentation, defining
  structures, syntax, and semantics of use.
- [ ] To describe the functional requirements of the system.
- [ ] To automate the documentation process.

<details>
<summary>Rationale</summary>
<p>

**Rationale:** Documentation manual is a practical handbook for maintainers, defining
structures/syntax/semantics (often referencing UML). Stakeholder overviews, functional requirements,
and automation all miss its maintainer guidance purpose.

</p>
</details>
