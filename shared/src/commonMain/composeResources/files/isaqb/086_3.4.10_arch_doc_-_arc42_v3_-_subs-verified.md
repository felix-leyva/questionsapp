## Question 1

What is the primary purpose of the ARC42 standard?

- [ ] To define a specific programming language for software development.
- [x] To provide a comprehensive framework for documenting software architectures, ensuring clarity,
  consistency, and completeness.
- [ ] To automate the process of software deployment.
- [ ] To manage project budgets and timelines.

<details>
<summary>Rationale</summary>
<p>

**Rationale:** arc42 provides a comprehensive framework for architecture documentation ensuring
clarity, consistency, and completeness in communicating decisions. Programming language definition,
deployment automation, and budget/timeline management are separate concerns.

</p>
</details>

## Question 2

Which of the following sections are typically included in an ARC42 documentation?

- [x] Introduction and goals.
- [x] Constraints.
- [x] Context and scope.
- [x] Solution strategy.
- [x] Building block view.
- [x] Runtime view.
- [x] Deployment view.
- [x] Crosscutting concepts.
- [x] Architectural decisions.
- [x] Quality requirements.
- [x] Glossary.
- [ ] Detailed code implementation.

<details>
<summary>Rationale</summary>
<p>

**Rationale:** arc42 includes all listed sections: Introduction/goals, Constraints, Context/scope,
Solution strategy, Building block/Runtime/Deployment views, Crosscutting concepts, Decisions,
Quality requirements, Glossary. Detailed code implementation is outside arc42's architectural
documentation scope.

</p>
</details>

## Question 5

What are the general benefits of using a standard structure like ARC42 for architecture
documentation?

- [ ] It forces all projects to use the same architectural style.
- [x] It promotes consistency, ensures completeness, and increases efficiency by minimizing
  structuring effort and facilitating navigation.
- [ ] It eliminates the need for any human review of the documentation.
- [ ] It automatically generates all required diagrams.

<details>
<summary>Rationale</summary>
<p>

**Rationale:** arc42 promotes consistency, ensures completeness, increases efficiency (minimal
structuring effort, familiar navigation). Architectural style forcing, human review elimination, and
automatic diagram generation all miss standard structure's organizational benefits.

</p>
</details>
