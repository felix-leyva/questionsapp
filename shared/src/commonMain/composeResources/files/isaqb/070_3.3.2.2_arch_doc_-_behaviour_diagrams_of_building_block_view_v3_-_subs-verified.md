## Question 1

What is the primary purpose of "State Diagrams" in the building block view?

- [ ] To show the physical deployment of components.
- [x] To represent object states and transitions in lifecycles.
- [ ] To model business processes and workflows.
- [ ] To depict state change over time based on triggers.

<details>
<summary>Rationale</summary>
<p>

**Rationale:** State diagrams show object states and transitions, modeling reactive system lifecycles (protocol, control software). Physical deployment (Deployment diagrams), business processes (Activity diagrams), and time-based changes (Timing diagrams) are different diagram purposes.

</p>
</details>

## Question 2

For what type of systems are "Timing Diagrams" primarily used?

- [ ] Business process modeling.

- [ ] User interface design.

<details>
<summary>Rationale</summary>
<p>

**Rationale:** Timing diagrams model real-time and embedded system timing constraints, showing state changes over time based on triggers. Business processes (Activity diagrams), OO design (Class diagrams), and UI design are separate concerns.

</p>

- [ ] The static structure of a system's components.

## Question 4

In the example of a state diagram for a meeting, what are the three main states a meeting can be in?

- [ ] Scheduled, Postponed, and Due.
- [x] Active, Has Taken Place, and Cancelled.
- [ ] Started, In Progress, and Finished.
- [ ] Open, Closed, and Archived.

<details>
<summary>Rationale</summary>
<p>

</p>
</details>

## Question 5

According to the state diagram example, when can an active meeting no longer be postponed?

- [ ] As soon as it is scheduled.
- [ ] After it has been cancelled.
- [x] When start time passes and it becomes due.
- [ ] Only if it has already taken place.

<details>
<summary>Rationale</summary>
<p>

**Rationale:** Active meetings cannot be postponed once start time passes (becomes due). Scheduling, cancellation, and completion don't prevent postponement—only the due state transition prevents further postponement.

</p>
</details>

## Question 6

What is the primary purpose of "Behavior Diagrams" in UML?

- [ ] To show the static structure of a system.
- [x] To show the dynamic behavior of a system.
- [ ] To describe the deployment of a system.
- [ ] To illustrate the physical components of a system.

<details>
<summary>Rationale</summary>
<p>

**Rationale:** Behavior diagrams show dynamic system behavior. Static structure (Structure diagrams), deployment (Deployment diagrams), and physical components (Deployment View) are separate UML diagram categories.

</p>
</details>
