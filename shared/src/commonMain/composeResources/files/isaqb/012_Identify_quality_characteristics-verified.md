## Question 1

What standard does the text recommend using to support the identification of quality characteristics in architectural design?

- [ ] ISO 9001 quality management
- [ ] IEEE 1471 architecture description
- [x] DIN standard 25010 quality attributes
- [ ] ISO/IEC 27001 information security

<details>
<summary>Rationale</summary>
<p>

**Rationale:** DIN 25010 describes quality attributes for software systems. ISO 9001 covers general quality management, IEEE 1471 addresses architecture description, and ISO 27001 focuses on security—different standards for different purposes.

</p>
</details>

- [ ] System architects
- [ ] Development team
- [x] End users

<details>
<summary>Rationale</summary>

## Question 4

How can an architect influence the *internal* quality attributes of a system?

- [ ] By selecting appropriate UI/UX design patterns.
- [ ] By establishing service level agreements.
- [x] By using architectural styles for maintainability.
- [ ] By implementing monitoring and observability.

<details>
<summary>Rationale</summary>
<p>

**Rationale:** Architects influence internal quality attributes through architectural styles that increase maintainability. UI patterns, SLAs, and monitoring affect external attributes or operational concerns, not internal structural quality.

</p>
</details>

## Question 5

How does an architect typically control the *external* quality attributes like performance and security?

- [ ] By establishing coding standards and guidelines.
- [x] By making appropriate technology decisions.
- [ ] By focusing on modular design patterns.
- [ ] By defining unit testing and review processes.

<details>
<summary>Rationale</summary>
<p>

**Rationale:** External quality attributes are controlled through technology selection decisions (frameworks, databases, security libraries). Coding standards, modular design, and testing affect internal quality and development process, not runtime external attributes.

</p>
</details>
