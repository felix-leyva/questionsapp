## Question 1

What standard does the text recommend using to support the identification of quality characteristics
in architectural design?

- [ ] ISO 9001 for quality management systems
- [ ] IEEE 1471 for software architecture description
- [x] DIN standard 25010
- [ ] ISO/IEC 27001 for information security

<details>
<summary>Rationale</summary>
<p>

**Rationale:** DIN 25010 describes quality attributes for software systems. ISO 9001 covers general
quality management, IEEE 1471 addresses architecture description, and ISO 27001 focuses on
security—different standards for different purposes.

</p>
</details>

## Question 2

According to the text, which of the following are classified as "internal" quality attributes, which
are particularly important for developers?

- [ ] Usability and Security for end-user protection
- [x] Maintainability and Portability
- [ ] Performance Efficiency and Reliability for runtime behavior
- [ ] Functional Suitability and Compatibility for feature completeness

<details>
<summary>Rationale</summary>
<p>

**Rationale:** Maintainability and Portability are internal quality attributes crucial for
developers. Usability, Security, Performance, Reliability, Functional Suitability, and Compatibility
are external attributes important to users.

</p>
</details>

## Question 3

For whom are the "external" quality attributes such as usability, performance, and security
considered particularly important?

- [ ] Project managers tracking delivery metrics
- [ ] The architects designing the system structure
- [ ] The development team implementing features
- [x] The users

<details>
<summary>Rationale</summary>
<p>

**Rationale:** External quality attributes (usability, performance, reliability, compatibility,
security, functional suitability) are particularly important for users who directly experience them.
Project managers, architects, and developers have different primary concerns.

</p>
</details>

## Question 4

How can an architect influence the *internal* quality attributes of a system?

- [ ] By selecting appropriate UI/UX design patterns for interfaces.
- [ ] Primarily through establishing service level agreements with users.
- [x] By using architectural styles that increase maintainability.
- [ ] By implementing comprehensive monitoring and observability solutions.

<details>
<summary>Rationale</summary>
<p>

**Rationale:** Architects influence internal quality attributes through architectural styles that
increase maintainability. UI patterns, SLAs, and monitoring affect external attributes or
operational concerns, not internal structural quality.

</p>
</details>

## Question 5

How does an architect typically control the *external* quality attributes like performance and
security?

- [ ] By establishing coding standards and development guidelines.
- [x] By making appropriate decisions about which technology to use.
- [ ] By focusing on modular design and component decomposition.
- [ ] By defining comprehensive unit testing and code review processes.

<details>
<summary>Rationale</summary>
<p>

**Rationale:** External quality attributes are controlled through technology selection decisions (
frameworks, databases, security libraries). Coding standards, modular design, and testing affect
internal quality and development process, not runtime external attributes.

</p>
</details>
