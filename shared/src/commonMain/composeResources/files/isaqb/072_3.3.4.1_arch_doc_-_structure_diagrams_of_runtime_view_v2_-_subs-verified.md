## Question 1

What is the primary purpose of "Object Diagrams" in the runtime view?

- [ ] To show the static type structure of an object-oriented system.
- [x] To represent instances of classes, showing a snapshot of the system at a particular moment,
  and to understand object structures at runtime.
- [ ] To depict the internal structure of a class and its collaborations.
- [ ] To illustrate the deployment of software components on hardware.

<details>
<summary>Rationale</summary>
<p>

**Rationale:** Object diagrams show class instances as runtime snapshots, revealing runtime object
structures. Static type structure (Class diagrams), class internals (Composite Structure diagrams),
and deployment (Deployment diagrams) are separate purposes.

</p>
</details>

## Question 2

Why can "Object Diagrams" sometimes appear simpler than their corresponding "Class Diagrams"?

- [ ] Object diagrams do not show any relationships between objects.
- [x] They show only concrete objects, not complex inheritance hierarchies or abstract interfaces.
- [ ] They are only used for very small systems.
- [ ] They do not represent actual instances of classes.

<details>
<summary>Rationale</summary>
<p>

**Rationale:** Object diagrams appear simpler showing only concrete objects, omitting inheritance
hierarchies and abstract interfaces. They do show relationships, work for all system sizes, and
specifically represent class instances.

</p>
</details>

## Question 3

What is the purpose of "Composite Structure Diagrams"?

- [ ] To show the dynamic behavior of a system over time.
- [x] To depict the internal structure of a class and the collaborations that this structure makes
  possible, useful for detailed design.
- [ ] To represent the states of an object and transitions between them.
- [ ] To illustrate the flow of control between different activities.

<details>
<summary>Rationale</summary>
<p>

**Rationale:** Composite Structure diagrams depict class internal structure and collaboration
possibilities for detailed design. Dynamic behavior (Sequence diagrams), state transitions (State
diagrams), and activity flow (Activity diagrams) are separate UML purposes.

</p>
</details>
