## Question 1

What is the primary focus of this chapter regarding software architecture?

- [ ] Software development methodologies.
- [x] The quality of software architectures and how to ensure it.
- [ ] Project management techniques.
- [ ] Specific programming languages.

<details>
<summary>Rationale</summary>
<p>

**Rationale:** Chapter focuses on software architecture quality and ensuring it. Development
methodologies, project management, and programming languages are separate software engineering
concerns outside architecture quality focus.

</p>
</details>

## Question 2

What types of evaluation methods for software architectures will be introduced in this chapter?

- [ ] Only qualitative methods.
- [ ] Only quantitative methods.
- [x] Qualitative and quantitative evaluation methods.
- [ ] Only automated evaluation methods.

<details>
<summary>Rationale</summary>
<p>

**Rationale:** Chapter introduces both qualitative (requirement fulfillment) and quantitative (
metrics-based) evaluation methods. Qualitative-only, quantitative-only, and automated-only all miss
the comprehensive dual-method approach.

</p>
</details>

## Question 3

What specific method for quality assessment will be discussed in detail?

- [ ] Agile Scrum.
- [x] ATAM (Architecture Trade-off Analysis Method).
- [ ] Test-Driven Development (TDD).
- [ ] Domain-Driven Design (DDD).

<details>
<summary>Rationale</summary>
<p>

**Rationale:** ATAM (Architecture Trade-off Analysis Method) will be discussed in detail. Agile
Scrum, TDD, and DDD are development approaches, not architecture quality assessment methods.

</p>
</details>

## Question 4

What topic will be the starting point for discussing the quality of software architectures in this
chapter?

- [ ] Software design patterns.
- [x] Technical debt.
- [ ] User interface design.
- [ ] Database management.

<details>
<summary>Rationale</summary>
<p>

**Rationale:** Technical debt is the starting point for quality discussion (implied cost of
non-optimal solutions). Design patterns, UI design, and database management are implementation
concerns, not quality discussion starting points.

</p>
</details>
