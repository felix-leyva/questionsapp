## Question 1

What is the primary purpose of a "Deployment Diagram"?

- [ ] To show static structure of software components.
- [x] To show artifacts deployed on hardware nodes.
- [ ] To illustrate dynamic interactions at runtime.
- [ ] To describe external context and interfaces.

<details>
<summary>Rationale</summary>
<p>

**Rationale:** Deployment diagrams show execution architecture—artifacts (software) deployed on nodes (hardware). Static structure (Class diagrams), dynamic interactions (Sequence diagrams), and external context (Context View) are separate UML/view purposes.

</p>
</details>

## Question 2

In a deployment diagram, what do "nodes" represent?

- [ ] Software components or applications.
- [x] Hardware devices or execution environments.
- [ ] Logical connections between components.
- [ ] Data flows within the system.

<details>
<summary>Rationale</summary>
<p>

**Rationale:** Nodes represent hardware devices or execution environments (web browser on PC). Software components (artifacts), logical connections, and data flows are separate deployment diagram elements or concerns.

</p>
</details>

## Question 3

In a deployment diagram, what do "artifacts" represent?

- [ ] Hardware devices or servers.
- [x] Software components deployed on nodes.
- [ ] Network connections between nodes.
- [ ] The overall system architecture.

<details>
<summary>Rationale</summary>
<p>

**Rationale:** Artifacts represent software components deployed on nodes or pre-installed in execution environments. Hardware devices (nodes), network connections (communication paths), and overall architecture (multiple views) are separate concerns.

</p>
</details>

## Question 4

What is the utility of a deployment diagram for development and operations teams?

- [ ] It helps them design the user interface.
- [x] It helps understand execution architecture.
- [ ] It provides view of internal business logic.
- [ ] It defines the functional requirements.

<details>
<summary>Rationale</summary>
<p>

**Rationale:** Deployment diagrams help dev-ops understand execution architecture and aid network design/communication. UI design, business logic details, and functional requirements are separate concerns outside deployment scope.

</p>
</details>
