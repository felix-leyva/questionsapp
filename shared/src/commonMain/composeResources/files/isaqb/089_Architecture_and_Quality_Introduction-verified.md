## Question 1

What is the primary focus of Chapter 4, as introduced by Dela?

- [ ] Software development methodologies.
- [x] The quality of an architecture and how to evaluate it.
- [ ] Project management techniques.
- [ ] Specific programming languages.

<details>
<summary>Rationale</summary>
<p>

**Rationale:** Chapter 4 focuses on architecture quality and evaluation methods. Development
methodologies, project management, and programming languages are separate software engineering
topics outside quality evaluation scope.

</p>
</details>

## Question 2

What will be the basis for evaluating quality in this chapter?

- [ ] Code reviews.
- [x] Scenarios derived from quality characteristics organized in utility trees.
- [ ] Automated testing.
- [ ] User feedback.

<details>
<summary>Rationale</summary>
<p>

**Rationale:** Quality evaluation uses scenarios derived from quality characteristics organized in
utility trees. Code reviews, automated testing, and user feedback are evaluation inputs, not the
systematic scenario-based evaluation basis.

</p>
</details>

## Question 3

What method for quality assessment will be learned in this chapter?

- [ ] Agile Scrum.
- [x] The Architecture Trade-off Analysis Method (ATAM).
- [ ] Test-Driven Development (TDD).
- [ ] Domain-Driven Design (DDD).

<details>
<summary>Rationale</summary>
<p>

**Rationale:** The chapter teaches ATAM (Architecture Trade-off Analysis Method) for quality
assessment. Agile Scrum, TDD, and DDD are development methodologies/approaches, not architecture
quality assessment methods.

</p>
</details>
